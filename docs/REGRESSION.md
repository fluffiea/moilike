# 重构验收：基线与回归清单

## 1. 测试云环境（真机验证前必做）

1. 云开发控制台 → 环境 → 新建一个测试环境（按量计费，图片缩略图处理需要按量计费环境）。
2. 在测试环境建集合：`users`、`daily_posts`、`daily_comments`、`report_posts`、`bind_requests`、`letters`、`expenses`、`kitchens`、`kitchen_categories`、`kitchen_dishes`、`kitchen_orders`，权限全部选「仅云函数可读写」。
3. 按 [DATABASE.md](./DATABASE.md) 建索引。
4. `project.private.config.json` 里不要写死 env；开发者工具顶部「云开发」切到测试环境后，上传部署 `cloudfunctions/api`（云端安装依赖）。
5. 用两个微信号（体验成员）登录，互相结伴后跑下面的回归清单。

## 2. 性能基线（重构前，按代码统计）

「云调用」指 `wx.cloud.callFunction` 次数；「串行段」指用户看到完整内容前必须依次等待的往返段数。

| 场景 | 重构前云调用 | 重构前串行段 | 重构后目标 |
|------|------|------|------|
| 冷启动（已登录）到朝夕页完整显示 | 5（`user.getProfile` x2、头像换链 x2、`letters.summary`） | 4，且登录页先阻塞 1 次才跳 Tab | 缓存直出，后台 1 次 `home.summary` |
| 浮生首屏 | 3（`daily.listDaily` + 配图换链 + 头像换链，跨 2 个函数） | 2 | 1 |
| 共鸣首个 Tab | 3（同上） | 2 | 1 |
| 日常详情 | 4（详情 + 评论并行，再配图 + 头像换链） | 2 | 1 |
| 从详情返回浮生 | 3（`getDailyFeedItem` + 2 次换链） | 2 | 0（本地 store 同步） |
| 报备详情 | 3 | 2 | 1 |
| 独白页每次显示 | 1~3（60 秒节流 + 2 次头像换链） | 2 | 0~1（读 store，后台刷新），另加 1 次 `expense.monthSummary`（`scope=total`）刷新「本月已花」 |
| 结伴页 | 3（面板 + 对方头像 + 申请人头像） | 2 | 1 |

服务端每个列表/详情请求额外先做 2~4 次 `users` 读取确认双向绑定；评论摘要每页最多拉 1000 条评论到内存。重构后只读 1 次本人文档（伴侣文档与业务查询并行），评论摘要改为帖子上的冗余字段。

真机实测方法：开发者工具「调试器 → Performance」录制冷启动；云开发控制台「云函数 → 日志」按 requestId 统计调用次数与耗时；重构前后各录 3 次取中位数填入下表。

| 冷启动到朝夕页可见（ms） | | |
| 浮生首屏图片可见（ms） | | |
| 日常详情可交互（ms） | | |

## 3. 手工回归清单

每项在 Android 与 iOS 各跑一遍（Skyline 渲染：开发版菜单 → 开发调试 → Switch Render → Skyline）。

**登录与资料**
- [ ] 全新微信号首次进入：显示登录页，选头像 + 昵称后进入朝夕
- [ ] 已登录冷启动：不经过登录页，直接显示缓存内容，随后静默刷新
- [ ] 清除缓存后冷启动：自动识别云端已有资料并直接进入
- [ ] 独白页退出登录 → 登录页显示已填好的资料，点「进入」恢复；杀进程重进仍停在登录页
- [ ] 编辑资料：改头像、昵称、签名后返回，独白与朝夕立即更新
- [ ] 偏好设置：切换共鸣默认筛选，回到共鸣页生效

**结伴与纪念日**
- [ ] A 复制绑定码，B 输入并发送申请；B 页面显示「等待对方回应」
- [ ] A 在结伴页看到申请，拒绝后 B 可再次申请；同意后双方都显示已结伴
- [ ] 设置纪念日后双方朝夕页计时一致，且秒数每秒跳动
- [ ] 未结伴时：朝夕、点单、共鸣都有引导；素笺从朝夕进入，未结伴时是写信引导

**共鸣（报备）**
- [ ] 发布带标签、记录时间、配图的报备；新增 / 长按删除自定义标签
- [ ] 顶栏为全部｜待我回应｜我发的；新账号默认进待我回应；偏好里已经存过的全部 / 我发的不会被改掉
- [ ] 待我回应只含对方还没贴贴纸的报备（没打开的、打开了还没贴的都算）；共鸣 Tab 数字和分段旁的计数一致，为 0 时两边都不显示
- [ ] 进详情不用点按钮也会记成已打开；点一张贴纸就是已回心，这条离开待我回应；再点另一张会换掉上一张，只留最新
- [ ] 我发的：已回心能看到贴纸和相对时间；只打开、还没贴时显示「对方已打开 · 暂未回心」
- [ ] 详情里没有「标记已阅」，也没有文字评价
- [ ] 改一条对方已经回心的自己的报备：保存前会确认贴纸和时间都还留着；确认后不清空
- [ ] 三个筛选切换与左右滑动一致；返回列表时状态已更新
- [ ] 编辑 / 删除自己的报备

**素笺（信件从朝夕进入，不再占第二个 Tab）**
- [ ] 朝夕页有「素笺」入口；写信（选类型、自定义类型、标题、正文、配图）后回到列表能看到
- [ ] 读信；自己的信可编辑，改完仍是同一封，并标明「改过」
- [ ] 删除自己寄出的信；对方不能改、不能删
- [ ] 信件列表缩略图正常显示（含对方寄来的图片）

**记账（独白入口，不是第五个 Tab）**
- [ ] 未结伴也能记一笔；记账页没有「我的｜对方」。偏好设置里可以改「记账可见性」，底注是「结伴后对对方生效」
- [ ] 独白列表「记账」右侧仍只统计我的本月已花，不把对方算进去；点进去是记账页，底部仍是朝夕｜点单｜共鸣｜独白。记一笔始终记在自己账上
- [ ] 结伴后，对方设为不可见时，记账页仍是自己的账本，没有切换，也没有「对方暂未开放」
- [ ] 对方开放仅汇总或全部明细后，才出现「我的｜对方」。滑块左右移动，月份留在原处。全部明细时能看到完整流水，详情只读（有记录人，没有编辑和删除）
- [ ] 把可见范围改成仅汇总：对方只见月合计和一级占比，没有流水和详情，并写着「对方仅开放汇总，不可查看明细」
- [ ] 结伴前已经记的流水，开放后对方按当前范围能看到；不能改、不能删对方的账
- [ ] 金额必填且大于 0；一级、二级都要选；时间默认现在，可改，不能选未来；备注最多 50 字
- [ ] 流水按时间倒序；可切换自然月，不能切到未来月
- [ ] 本月合计、TOP3、一级条形图；点一级进入二级占比和该分类明细
- [ ] 看当前月时标明「本月未结束」；没有上月支出时环比是「—」；完整月均旁注「不含本月」
- [ ] 编辑后金额、分类、时间、备注都更新；改到别的月份后，回到账本会切到那个月。删除有二次确认，确认后从列表消失

**小厨房（第二 Tab 点单；独白经营。先部署 api，并建好 kitchens、kitchen_categories、kitchen_dishes、kitchen_orders）**
- [ ] 底栏第二项是点单，没有第五个 Tab；点单 Tab 上没有待接单红点
- [ ] 未结伴点单：大标题「先结伴才能点单」，可以去结伴；也可以看看自己的厨房
- [ ] 已结伴但对方没建厨：大标题「Ta 还没有开厨房」
- [ ] 独白「我的厨房」未建时是创建页；创建后菜单是空的，没有「心意 / 陪伴 / 日常」和示例菜。空菜单写着从右下角加菜，没有分类可先起一个
- [ ] 管理分类空态可以新增；有菜的分类不能删；没有拖拽排序
- [ ] 新建菜品要选分类，没有默认「心意」；没有分类时可以顺手新建再挂上。名称必填，说明可空，封面可拍照或相册，默认为上架。没有快捷标签
- [ ] 对方已建厨但没有上架菜：点单仍显示厨房名，主体是「厨房还是空的」
- [ ] 有上架菜后：左分类和右侧按分类的菜段联动。点分类跳到该段，滚动菜品时左栏高亮跟随。顶栏可以搜菜名，没有结果是「没有找到相关菜」
- [ ] 菜卡没有价格。没有封面是「暂无封面」。点＋直接加入 1 份，不出现规格弹层和快捷标签。份量在购物车和确认页里改
- [ ] 没有真实完成记录时，菜品行不显示「常点」或次数；完成满 5 单后才显示「常点」。不出现月售
- [ ] 确认页标题是「确认下单」，只有整单备注，没有支付。自己的厨房可以预览到确认页，但不能提交。提交后是待接单
- [ ] 我的订单：待接单可以取消；进行中和完成后不能取消。状态为「完成」的订单可以再来一单，还在架上的菜放回购物车，下架的跳过并提示，不带上次备注
- [ ] 独白经营：分段是待接单、进行中、完成。待接单可接单，进行中可完成。没有拒单。待接单数字只出现在独白「我的厨房」右侧，写成「N 待接」

- [ ] 底部按钮、悬浮按钮不被 Home Indicator 遮挡
